## 11. TradeOrderService.ExecuteTradeAsync — Step-by-Step

**File:** `Boyka.Application/Services/TradeOrderService.cs`

1. Load `TradingAccount` by `request.TradingAccountId` → 404 `KeyNotFoundException` if missing.
2. `account.IsActive` must be `true` → `InvalidOperationException` if not.
3. `request.Direction` must be `Buy` or `Sell` → `InvalidOperationException` if neither (redundant with enum binding but explicit).
4. `request.Volume > 0` → `InvalidOperationException` if not.
5. `request.Volume <= 100` → `InvalidOperationException` if exceeded.
6. `EntryPrice`, `StopLoss`, `TakeProfit` all `> 0` → `InvalidOperationException` if any are zero/negative.
7. Directional SL/TP validation:
   - Buy: `StopLoss < EntryPrice` AND `TakeProfit > EntryPrice`
   - Sell: `StopLoss > EntryPrice` AND `TakeProfit < EntryPrice`
8. Load `RiskProfile` for the account where `IsEnabled = true`. If found:
   - `request.Volume <= riskProfile.MaximumLotSize`
   - Count of orders with `Status == Pending || Status == Accepted` must be `< riskProfile.MaximumOpenPositions`
9. Create `TradeOrder` with `Status = TradeOrderStatus.Accepted`, persist with `SaveChangesAsync()`.
10. Call `_mockExecutionService.ExecuteAsync(order)` → returns `TradeExecution` object.
11. Set `execution.TradeOrderId = order.Id`, add to `TradeExecutions`, call `SaveChangesAsync()`.
12. Update `order.Status`:
    - `Success` → `TradeOrderStatus.Executed`
    - Anything else → `TradeOrderStatus.Rejected`
13. Call `SaveChangesAsync()` again.
14. Return `MapToResponse(order)`.

**Three separate `SaveChangesAsync()` calls** (after order create, after execution create, after order status update). This means partial persistence is possible if steps 2 or 3 fail mid-way — a Phase 2 concern for robustness.

**Phase 2 impact:** This method will need to diverge. For real MT5 execution, step 10 becomes a queue dispatch (not synchronous), so steps 11–13 will not happen in the same HTTP request. The service will need a new code path (or a new method) that:
- Sets order status to `Queued` after persisting.
- Returns immediately with `202 Accepted` and the order response.
- Leaves execution and final status to be recorded by the EA acknowledgement callback.
